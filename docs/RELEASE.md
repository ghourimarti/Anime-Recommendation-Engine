# Releasing the Anime Recommender

One git tag produces every artifact the deployments consume. Nothing is rebuilt
downstream: kind (Phase 7), DigitalOcean (Phase 8) and AWS (Phase 9) deploy the
same signed digests.

Workflow: [`.github/workflows/release.yml`](../.github/workflows/release.yml)

## What a release produces

| Artifact | Where | Notes |
|---|---|---|
| api / web / worker images | `ghcr.io/ghourimarti/anime-recommender/<component>:vX.Y.Z` | Source of truth. Also tagged `:sha-<7>` |
| Public mirror | `docker.io/ghourimarti/anime-recommender-<component>:vX.Y.Z` | **Same digest** as ghcr, or the release fails |
| Helm chart | `oci://ghcr.io/ghourimarti/charts/anime-recommender` version `X.Y.Z` | Chart version = app version |
| SBOM per image | GitHub Release asset + signed cosign attestation | SPDX JSON, generated by syft |
| Digest record | `release/images.lock`, `release/values-images.yaml` | Release assets + automatic PR |

Every image and the chart are signed with **cosign keyless**: no signing key exists
anywhere. The signature binds the digest to this repository's release workflow run.

## Before the first release (one-time)

1. **Repository secrets** (Settings → Secrets and variables → Actions):
   `GHCR_PAT` (classic PAT with `write:packages`), `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`.
2. **Allow the PR step:** Settings → Actions → General → Workflow permissions →
   enable *Allow GitHub Actions to create and approve pull requests*.
3. **After the first publish, make the ghcr packages public** (decision R6).
   GitHub creates new packages as private and offers no API to change that:
   open each package (`anime-recommender/api`, `/web`, `/worker`, `charts/anime-recommender`)
   → Package settings → Change visibility → Public. The MinIO mirror stays **private** (AGPL).
4. Docker Hub creates the three `anime-recommender-*` repositories on first push.

## Dry run (recommended before every tag)

Actions → **release** → Run workflow → leave *publish* unticked, or:

```bash
gh workflow run release.yml -f publish=false
```

A dry run builds all three images on their pinned bases, runs the Trivy gate,
generates SBOMs, runs render-verify and packages the chart. It pushes, signs and
publishes nothing. Signing can only be exercised by a real tag.

## Cut a release

```bash
git tag v0.1.0
git push origin v0.1.0
```

The workflow then:

1. builds each image **once** and loads it on the runner,
2. fails on fixable HIGH/CRITICAL vulnerabilities (Trivy),
3. generates the SBOM,
4. pushes that same image to ghcr and Docker Hub and **fails if the digests differ**,
5. signs both references, attests the SBOM, and verifies both the way a consumer would,
6. render-verifies, packages, pushes and signs the chart,
7. writes the digest record, publishes the GitHub Release and opens a PR with the record.

A tag like `v1.0.0-rc1` matches the trigger but is treated as a dry run: only
plain `vX.Y.Z` tags publish.

## Verify before you deploy

```bash
IMAGE=ghcr.io/ghourimarti/anime-recommender/api@sha256:<digest from release/images.lock>

cosign verify "$IMAGE" \
  --certificate-identity-regexp '^https://github\.com/ghourimarti/Anime-Recommendation-Engine/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com

cosign verify-attestation "$IMAGE" --type spdxjson \
  --certificate-identity-regexp '^https://github\.com/ghourimarti/Anime-Recommendation-Engine/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

The identity pins the signature to **this repository's release workflow on a
version tag**. A signature made anywhere else, including a fork or a branch run,
does not verify.

## Deploy by digest

```bash
helm install anime oci://ghcr.io/ghourimarti/charts/anime-recommender --version 0.1.0 \
  -f infra/k8s/helm/anime-recommender/values-<vendor>.yaml \
  -f infra/k8s/helm/anime-recommender/values-<env>.yaml \
  -f release/values-images.yaml
```

`values-images.yaml` sets `image.<component>.digest`, which the chart prefers over
any tag. The web image reads its site URL and Clerk publishable key at runtime
(`web.siteUrl`, `web.clerkPublishableKey`), so the same image works on every hostname.

## Build the bundle locally

```bash
make package VERSION=0.1.0
```

Builds the three images on the pinned bases from `base-images.lock`, runs
render-verify and writes `dist/anime-recommender-0.1.0.tgz`. Nothing is pushed,
scanned or signed; that happens only in CI.

## Known caveats

- **`cd.yml` also runs on every `vX.Y.Z` tag** and fails at *Assume AWS role* until the
  AWS infrastructure exists (decision G5=C). Expected, and a recorded Phase 9 blocker:
  that workflow still builds its own ECR images, so EKS would not run these digests yet.
- **The first release may fail the Trivy gate** on a fixable HIGH vulnerability in a base
  image. That is the gate working: bump `base-images.lock` (`make base-images-refresh`)
  in its own commit and tag again.
- **Signing steps are only exercised by a real tag.** A dry run cannot prove them; watch
  the first published run.
